# Dependency security maintenance

The lockfile refresh updates transitive packages to patched releases. The
`serialize-javascript` override moves older consumers to the patched 7.x API
(Node 20+); the production build exercises those consumers. SockJS only calls
`require('uuid').v4()`, which remains available in the overridden CommonJS-capable
11.x release. Keep Docusaurus packages on matching versions; 3.10.2 includes
webpackbar 7, needed for compatibility with current webpack.

Use the pnpm version pinned in `package.json` (also used by both CI workflows).
pnpm 9 rejects the patch metadata generated by pnpm 10 during frozen installs.

## image-size 2.0.2 local patch

There is no published patched version for these advisories at the time of this
update:

- [ICNS infinite loop (GHSA-w3rx-r6r6-pgpr)](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr)
- [JXL / HEIF infinite loops (GHSA-5p2g-fcmc-qvqq)](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq)

Docusaurus's MDX loader uses this package. The pnpm patch rejects ICNS entries
shorter than their eight-byte header and prevents box lookup from returning
undersized boxes that can stop JXL/HEIF parser loops from advancing. It covers
all shipped CommonJS and ES module bundles, including the file and format APIs.

`pnpm test:security` runs malformed ICNS, HEIF and JXL fixtures in subprocesses
with a timeout, checks buffer/file and format-specific APIs in both module modes,
and checks valid image dimensions. The malformed fixtures derive from the
[original report](https://joshua.hu/image-size-infinite-loop-dos-vulnerabilities).

Version-based `pnpm audit` still reports these two advisories because the patched
package retains version 2.0.2. No advisories are suppressed. When an upstream fix
is released, replace the local patch with that version, regenerate the lockfile,
and rerun `pnpm test:security`, `pnpm audit`, and `pnpm build`.
